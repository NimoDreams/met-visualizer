# Specs

Specs define detailed behavior for features, workflows, APIs, schemas, or UI
surfaces.

Create a spec when a future implementer needs more precision than the roadmap
or issue description provides.

Recommended spec format:

- Problem or use case.
- Success criteria.
- User experience.
- Data model or API behavior.
- Edge cases.
- Testing expectations.
- Open questions.
